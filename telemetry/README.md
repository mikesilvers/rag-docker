# Optional local OpenTelemetry Collector

The application is disabled by default. Its supported settings and data policy
are in [the root README](../README.md#optional-backend-telemetry). Local collection
requires an explicit overlay **and** profile:

```sh
docker compose -f docker-compose.yml -f docker-compose.telemetry.yml --profile telemetry up -d
```

The overlay passes `RAG_OTEL_*` settings into the API container, defaults enabled,
and sends HTTP/protobuf to `http://otel-collector:4318`. Setting shell variables
without this wiring does not configure an existing API container; recreate it
after changes. The base Compose file still starts five services with telemetry
disabled. No application health dependency points to the Collector.

The Collector receives traces, operational metrics and private correlated logs.
Its default `debug` exporter prints counts at basic verbosity, not full payloads.
There is no external destination or hosted account. Docker logs rotate at 5 MiB,
two files. No ingestion port is published; only peers on the project's bridge
can reach 4318. This is a trusted local network, with no receiver authentication
or TLS. Do not publish it to an untrusted network. An operator adding host access
must use an explicit loopback binding such as `127.0.0.1:4318:4318`.

Disable application export while retaining the optional service:

```sh
RAG_OTEL_ENABLED=false docker compose -f docker-compose.yml -f docker-compose.telemetry.yml --profile telemetry up -d --force-recreate api
```

To return to base configuration, recreate the API using only `docker-compose.yml`
and stop the optional collector using the overlay/profile command. Disabling
telemetry does not stop API or background work. An unavailable receiver also
leaves application work usable; export is best effort and can lose data.

## Optional OTLP destination and runtime secret

`collector-otlp.example.yaml` is a complete alternative configuration using the
standard `otlp_http` exporter. For example, make a local operator-owned overlay:

```yaml
services:
  otel-collector:
    environment:
      RAG_COLLECTOR_DESTINATION: https://collector.example.invalid:4318
    volumes:
      - ./telemetry/collector-otlp.example.yaml:/etc/otelcol/config.yaml:ro
      - /absolute/outside-repository/otel-headers.yaml:/run/secrets/otel-headers.yaml:ro
```

The second file is a YAML mapping of header names to values, supplied at runtime
by the operator or secret manager. Keep it outside the repository and offline
bundle, with restrictive host permissions. Never commit real credentials. For
an unauthenticated private destination it may contain `{}`. Combine the operator
overlay after `docker-compose.telemetry.yml` and retain `--profile telemetry`.
HTTPS certificate verification stays enabled. The destination is an origin;
signal paths `/v1/traces`, `/v1/metrics`, `/v1/logs` are added by the exporter.
This optional destination creates only the egress explicitly chosen by the
operator. Do not print resolved secret fragments when troubleshooting.

Application-direct destination credentials use the different foundation format:
`RAG_OTEL_HEADERS_FILE` names a mounted JSON file. The local overlay requires no
such credentials; mount that file and add its environment setting explicitly
in an operator overlay if bypassing the Collector. Any application-direct
credential requires an HTTPS endpoint, including loopback; plaintext HTTP
is accepted only without credentials. Duplicate header names are rejected
case-insensitively, including repeated JSON keys.

## Bounds, sampling and diagnosis

Collector 0.162.0 is pinned by multi-platform digest in Compose and `image.json`.
Only Linux amd64/arm64 have trusted offline config-ID entries. The Collector is
limited to 256 MiB and 0.5 CPU. Each signal pipeline uses a 192 MiB memory limiter
(32 MiB spike allowance, checked each second) followed by maximum 128-record batches
and a 1s batch timeout. The destination exporter has a 32-request queue, one
consumer, nonblocking overflow, 2s request timeout and retries bounded to 10s
(initial 1s, maximum interval 5s). These are per-signal queues, not byte limits or
a global 32-record cap. Container memory limits provide the ultimate memory
bound. Export shutdown uses a 10s container grace period.

Application queues, timeout, sampling, flush and shutdown bounds remain those
in the root README. Trace sampling can omit spans while metrics and logs remain
present, so not every log identity necessarily has a retained trace. No prompt,
answer, source text, file/path, credential, cookie, durable job ID or arbitrary
exception text should appear in exported telemetry. Job log correlation tokens
are generated by the application; they never authorize work or enter metric
labels. This is not durable security audit storage.

Check application settings inside the recreated container, Collector startup
logs and basic signal counts, DNS/network reachability and receiver status.
A healthy API does not establish Collector/export health. Missing signals can
reflect disabled flags, sampling, queue overflow, rejected destination data or
outage. Queue saturation/restart drops are possible; there is no persistent
queue. Operators own downstream access control, retention, deletion and storage
cost. Local log rotation is not a backend retention policy.

## Offline bundle

Default packaging/install commands retain their five-image behavior. To include
the optional image, first pull the exact `image` reference in `telemetry/image.json`
on the packaging machine, then run (Python 3.11+ required for this optional path):

```sh
bash package-offline.sh --telemetry rag-docker-offline.tar
# On the offline machine after extracting the bundle:
bash install-offline.sh --telemetry
```

This adds `offline/collector.tar` and an integrity/platform manifest. A bundle
contains the packaging host's loaded platform image, not both architectures.
The installer fails locally on missing optional payload or unsupported/mismatched
architecture. It verifies config identity against the tracked pinned allow-list
and every layer against that config before passing a reconstructed, tag-free
archive to Docker. Archive-provided tags/indexes cannot select another image.
It then starts with the checked local image ID and `--pull never --no-build`;
registry digest aliases need not survive Docker save/load. Metadata checksums
alone are not authenticity proofs: obtain the whole source/bundle from a trusted
publisher. Runtime secret files and ignored planning documents are excluded.

## Acceptance and limits

See [the disposable verification guide](../scripts/verify/README.md). Both the
normal full run and `stack.sh run --telemetry` are required for delivery evidence.
The enabled run captures actual protobuf after the pinned Collector for real
synthetic query, concurrent background jobs, restarts, disabled mode, stopped
Collector and slow downstream receiver. Capture overflow fails inspection.
It records latency samples and CPU/memory observations; it does not claim zero
overhead, lossless export or production performance. Source/configuration tests
alone do not establish this end-to-end acceptance.

Offline preparation rejects truncated TAR end markers, nonzero trailing bytes
and malformed image/sidecar metadata before emitting an archive to load.
The optional package prints the matching `install-offline.sh --telemetry` command.
